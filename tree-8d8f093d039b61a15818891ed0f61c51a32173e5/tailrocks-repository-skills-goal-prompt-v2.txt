Read ./tailrocks-repository-skills-development-goal-v2.md IN FULL. It supersedes the prior specification. Preserve existing progress; do not create a competing implementation. Maintain requirements-to-evidence and GOAL/progress/HANDOFF records.

Implement repo-merge as one convenient entry point composing repository audit, convergence, existing PR-lifecycle skills, and eligible cleanup. Reuse owners and shared state, not duplicate policy. DEFAULT behavior is to compare, finish/fix justified improvements, independently review, satisfy applicable CI, ACTUALLY LAND them, verify the destination, and clean eligible sources. A report, prepared patch, opened PR, or queued merge is not completion. --audit-only explicitly selects read-only analysis.

Make --target-branch configurable end to end; its omitted value is literally main. Positional inputs are SOURCES; the flag names the DESTINATION. Support source branch A into target branch B, multiple sources into one target, and PRs into any authorized existing target. Never silently use current HEAD, a PR base, or the repository default instead. Missing/ambiguous targets must not cause fallback or creation. Main must remain untouched when another destination is selected.

Support mixed source selectors: branch names and qualified refs, #1145 or PR numbers, PR URLs, a repository /pulls URL, and /branches/all URL. Logical examples:
/repo-merge --target-branch=release/next feature/auth
/repo-merge --target-branch=main #1663 #157 #46
/repo-merge --target-branch=main https://github.com/jackin-project/jackin/pull/1103
/repo-merge https://github.com/jackin-project/jackin/pulls
/repo-merge --target-branch=integration https://github.com/jackin-project/jackin/branches/all

Bind one repository, resolve selectors deterministically, paginate lists, preserve literal # arguments, reject mixed-repository ambiguity, and deduplicate without losing provenance. Selected-source commands must not become global cleanup. --all-work explicitly selects the original host-wide clone/worktree/unfinished-work convergence workflow. No selectors must not imply all work. Implement --cleanup=resolved|none and scope-aware resumption.

Judge improvement against the FRESH SELECTED TARGET and its requirements, not main or source age. Recognize partial/squash/cherry-pick landings, successors, reverts, and target-specific dependencies. Preserve better destination behavior. Adapt only coherent improvements; finish valid unfinished goals. Bind review, CI, landing, idempotency, and cleanup receipts to the exact target. Verify the combined batch after target advances.

When a source PR targets another branch, preserve it and its remaining obligations; use a scoped adaptation PR into the requested destination rather than silently retargeting, closing, or deleting the original. Restore-test unique local state before deletion. Never delete a source still needed by another target or containing unresolved work. A merge into release is not a merge into main.

Verify native client invocation and argument transport. Claude plugin commands may require their plugin namespace; Codex uses its supported skill-selection/mention interface.
